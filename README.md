# Robust Attack-Type Classification on Noisy Network Traffic Data

CSCY413 Special Topics in Cybersecurity · Track: Trustworthy & Robust AI for Security Operations
Author: Dania Elnour (23002102) · Individual project

## Aim
Classify attack types from network-traffic features on the **UNSW-NB15** benchmark and test how **accurate**, **robust**, and **explainable** the classifier is when the data contains duplicates, extreme values, and a dominant feature.

**Research question.** How accurately can a machine-learning model classify attack types from network traffic features, how robust is it to extreme and corrupted values, and which features does it rely on?

| ID | Sub-question |
|----|--------------|
| RQ1 | How do baseline and tree-ensemble models compare on the official partition, and how do they compare with published results? |
| RQ2 | How do raw, clipped, and signed-log preprocessing affect accuracy and robustness? |
| RQ3 | How much does performance depend on a dominant feature (e.g. `sttl`), and how does it degrade under noise? |
| RQ4 | Which features drive predictions, and are the explanations stable? |

## Data
Dataset: UNSW-NB15 (Moustafa and Slay, 2015), official partition files `UNSW_NB15_training-set.csv` (175,341 records) and `UNSW_NB15_testing-set.csv` (82,332 records). Target: `attack_cat` (normal + nine attack categories). `id` and the binary `label` are **not** used as features.
Download: https://research.unsw.edu.au/projects/unsw-nb15-dataset
**Data files are not committed** (see `.gitignore`). Place them in `data/raw/` as described in `data/README.md`.
Free for academic use; users must cite the five papers listed on the dataset page.

## Key audit findings (first run on the official files)
- 175,341 training and 82,332 testing records, 42 features (3 nominal, 39 numeric), 10 classes; no missing, negative or infinite values.
- 42.4% of training rows repeat the feature values of another row; 8,541 testing rows (10.4%) match a training row; no row repeats when `id` is counted.
- 17.4% of training rows share identical features with a row of a different class (a ceiling on accuracy).
- `sttl = 31` occurs only in Normal records; `id` is ordered by class.
- 17 features are more than half zeros; nine features exceed 10^6.
- Normal is 31.9% of training but 44.9% of testing; KS and PSI show small feature-level shift.

## Reproducibility rules
- Fixed random seed (`42`) read from `configs/`.
- Folds are **stratified, grouped by a hash of the feature values, and shuffled** (both files are ordered by class), so identical rows never fall in different folds. Deduplicating the training partition first would remove 42.4% of rows (90% of Generic), so a deduplicated-training run is kept as a sensitivity check instead.
- `id` and the binary `label` are never used as features (`id` is ordered by class; `label` is a function of the target).
- All other fitted preprocessing (percentiles, scaling, one-hot categories) happens **inside** cross-validation folds.
- The official testing partition is used **once**, at the end, and never for fitting, tuning, or model selection.
- Every table and figure in the report is regenerated from a script or config in this repo.
